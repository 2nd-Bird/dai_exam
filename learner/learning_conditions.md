# 長男 — 学習が起動する条件 / 起動しない条件

updated: 2026-08-29

この文書は診断名から一般化するためではなく、実際の学習場面の観察から、教材設計と伴走方法を更新するための運用メモ。

## 1. 現時点の中心課題

**理解力不足より、課題着手・動機の起動が最大のボトルネック。**

簡単すぎる問題でも「分かるからできる」とはならない。  
一人でプリントに向かう条件では、丸をつけるだけ・1語入れるだけでも着手しないことがある。

逆に、興味・状況・対話が立ち上がると、同じ文法を意味に合わせて口頭で使える。

したがって教材の目標は、
`説明をもっと簡単にする` だけではなく、
**「意味のある状況 → とっさに言う → 最小限だけ書く」までを課題の中に埋め込むこと。**

## 2. うまくできる流れ

### A. 状況が先にある
- 人物、目的、危機、違和感、笑いなどがある。
- 「正体不明のプレイヤーがいる。誰だこいつ？」のように、発話する理由が明確。
- 文法問題ではなく、まず「この状況で何と言う？」になる。

### B. 本人が状況の中に入る
- 本人自身、ゲームのキャラクター、海外プレイヤーなどを登場させる。
- 正解を当てるより、役になって言う方が起動しやすい。

### C. 父とのライブなやりとり
- 父が横にいるだけでなく、反応を見て状況を動かすと強く起動する。
- ただし毎回ゼロから即興するのはコストが高い。
- プリント側に状況を用意し、父は「点火・演出の増幅」に寄せる。
- DAY5では、**本人が印刷された状況を読む → 問題に答える → 父が短くコメントする**流れが有効だった。
- 印刷された状況は父の即興コストを減らすが、現状はそれだけで自力着手までは起きない。
- 父が笑い・驚き・補足を入れて注意を共調整する仕事は依然大きく、20分の学習時間以上に伴走負荷が高い。教材側はこの負荷を少しでも肩代わりする。

### D. 構造をモジュールとして説明する
理解は速く、単なる丸暗記より構造の組み替えが効く。

例:
`you do`
→ 疑問のスイッチ `do`
→ `do you do?`
→ 「何を？」の `what`
→ `do you do what?`
→ whatを前へ
→ `What do you do?`

「なぜそうなるか」を短い変形として見せると入りやすい。

### E. 音・リズム・気分を使う
- 聴覚からの取り込みが強い。
- 抑揚、リズム、キャラクターの気分を乗せた発話を聞かせ、同じ感じで言わせると反復が成立する。
- 書字反復ではなく、口頭の3〜5連発で自動化回数を稼げる。

### E2. 対比マトリクス + 音で往復すると定着が速い
- DAY7では、`see a fox / saw a fox`、`It is cute. / It was cute.`、`eat / ate`、`go / went` のように、意味が近く時制だけ違う表現をマトリクス状に並べると理解が進んだ。
- 見て理解するだけでなく、現在→過去、過去→現在をリズムよく何度も発音すると呼び出しやすくなる。
- be動詞も `I am / You are / その他 is / 複数 are` のような短い呪文・リズムで覚えるのが速い。
- 紙上の問題数を増やす代わりに、**少数の対比を声で往復して反復数を稼ぐ**。

### F. 実際に英語が役立つ文脈
- ゲームの音声チャットで英語話者のやりとりに混ざることがある。
- 英語は完全な学校課題ではなく、実際の通信手段として薄く意味を持っている。
- 教材はこの実体験へ接続する。

### G. 主文法の周辺を「薄塗り」する
- 状況から主対象の英文を出した後、父がコメントする流れの中で周辺文法へ短く触れると入りやすい。
- 1場面で複数項目を正式に習得させるのではなく、主対象1つ + 周辺を軽く見せる。
- 後日の別場面で再会したときに「前にも見た」を増やすための薄い接触として使う。

### H. 数学は「途中を外に出す」と安定する
- 負の乗法を頭の中だけで処理すると誤答が出るが、`(-2)×(-2)=2×(-1)×2×(-1)=4×1=4` のように分解を書くと正答できる。
- 累乗も指数を見て一度、同じ数の積へ展開すると戻れる。
- 現段階では途中式は冗長な手続きではなく、**思考を保持する外部メモリ**として機能する。
- 安定してから省略する。最初から暗算化を目標にしない。

### I. 抽象量は具体物・具体値へ一度接地すると入る
- 文字式で量の意味が見えないと、記号を一塊として誤読したり、何を計算しているか見失うことがある。
- `a g` のような「文字+単位」は視覚的に分節し、必要なら「みかん1個 a g」のような具体物へ一度置き換える。
- `80-x` のような一般式を完成答えとして受け取りにくい場合は、まず `x=10 → 70` を確認し、その後 `xが何でも使える答えが80-x` と一般化へ戻す。

### J. 理解できたことと自動的に呼び出せることは別
- 概念理解は速くても、演習回数が少ない内容は公式・手順をその場で再構成しようとする。
- 反復は理解不足への罰ではなく、必要な知識を即時に呼び出せるようにする再遭遇として扱う。
- 数学では、途中式を書く欄を問題と答えの間に置き、頭内処理だけで飛ばしにくいレイアウトにする。

### M. 代数記号は「意味理解」と「記号処理の自動化」を分ける
- 代数では、個々の概念を説明できても、係数と文字、指数と文字、符号とかっこの作用域が自動的に1チャンクとして見えていないことがある。
- この段階で頭内処理を急ぐと、値を誤った係数へ結び付ける、定数項をx項へ吸収する、かっこ前のマイナスを一部にしか作用させない、という誤りが起きる。
- 「ケアレスミス」で一括せず、`結合 / 項の型 / 作用域 / 転記監視` のどこが崩れたかを見る。
- 教材では、問題→途中1行→答えを固定し、途中1行で数字と符号が元式から勝手に変わっていないことを確認する。
- 演習量を一度に増やすより、同じ規則を別問題で日をまたいで短く再登場させ、自動化する。

## 3. できない / 起動しにくい流れ

### A. プリントを置いて一人でやらせる
- 理解済み・極端に簡単でも着手しない。
- 「できる問題なら一人で進む」は現状成立しない。
- DAY5でも自力ではほぼ白紙だったため、状況文を印刷しただけで独力化したとはみなさない。

### B. 場所を変えれば自動的に学習モードになる、という前提
- 「図書館でやる」と決め、図書館が休みだと、児童館など代替場所へ自動的には切り替わらない。
- 場所そのものより「その場で何を始めるか」の起動が必要。
- 今後は `図書館が休み→児童館でAだけ` のような代替ルールを事前に明示する。

### C. 未実施を積み残しとして見せる
- 「昨日の裏をまだやっていない」「Bが残っている」は、枯渇しやすい意欲をさらに減らす。
- 未実施技能は後続DAYの新しい状況へ埋め込み、古い紙を負債化しない。

### D. 書くことを理解確認の唯一の手段にする
- 口頭なら意味に応じて正しく使える場面でも、筆記開始が強い障壁になる。
- 1周目は口頭利用を正式に評価し、書字は本番答案へ接続する少数問題に限定する。

### E. 夕食後・眠気が強い時間
- 共同なら進めても、利用可能時間が短くなる。
- 高優先内容をAに置き、Bは未実施でも致命傷にならない設計にする。

### F. C段階の概念と完全独力を同時に要求する
- まだ概念が不安定な内容を、暗算・一人・自宅の条件で同時に処理させると、数学理解と実行機能のどちらで止まったか分からなくなる。
- 「一人でできない = 分かっていない」とは判定しない。

## 4. 問題プリントの設計原則

1. **状況を先に印刷する。**
2. `まず口で言う → 1語穴埋め → 必要な箇所だけ全文` の順。
3. 1つの状況で1つの文法判断に絞る。
4. Aに最重要内容を置く。Bは余力枠。
5. 前日の未実施ページをそのまま再提出しない。
6. 前に扱った文法は、新しい状況の材料として自然に再登場させる。
7. 各DAYに「声だけ3連発」など口頭反復を入れ、少ない演習量を補う。
8. 説明は短くするが、本人が構造へ食いついたらモジュール型の説明を許容する。
9. 父との脱線は一律に排除しない。**学習を起動するための脱線**は必要コストとして扱う。
10. ただし脱線後は、同じ構文を口頭で数回使って学習量へ変換する。
11. 英語では、主対象を回答した後に周辺文法をコメントで薄く触るのは可。ただし1場面の正式到達目標は1つに保つ。
12. 父が面白い状況を毎回発明しなくても済むよう、プリントに人物・目的・違和感・危機のフックをあらかじめ書く。
13. 数学で符号・累乗・計算順序が不安定な間は、**途中1行を書くこと自体を正解手順に含める。**
14. 遅れを取り返すときは範囲を削らず、問題数・重複反復を減らす。1枚に新規事項を詰め込まない。

## 5. 当面の評価軸

各技能を以下に分けて見る。

- `理解`: 文の仕組みを説明・選択できる
- `状況利用`: 場面に応じて口頭で使える
- `即時想起`: ヒントなしで短時間に出る
- `答案化`: 手書きで必要な形を再現できる
- `自力着手`: 一人で課題を開始できる

現状、`理解 / 状況利用` は高くなりやすい一方、
`即時想起 / 答案化 / 自力着手` が別ボトルネックになっている。

これらを1つの「できる / できない」に潰さない。

数学についても同様に、`概念理解 / 手順再現 / 暗算化 / 自力着手` を分ける。  
たとえば負の乗法は、現状 `概念理解=C、途中式ありの手順再現=B〜A、自力着手は別評価` のように記録する。

## 6. 独力化の標準フロー

独力化は一気に要求せず、次の順で移す。

### Phase A — 共同で獲得
対象: 新規内容、C/D。

1. 場所と開始時刻を先に固定する。
2. 最初の1〜2問を父と開始する。
3. 例・図・途中式を使って少数問だけ処理する。
4. **1枚を終了単位**にする。
5. 父は「どこで止まったか」を記録する。

### Phase B — body-double
対象: B、手順を見れば戻れる内容。

- 同じ机/部屋にいるが、最初は口を出さない。
- 止まったときだけ例を指す、またはヒントを1文。
- 3問程度連続で滑らかなら、その区間を独力候補にする。

### Phase C — 短い独力
対象: Aまたは安定したB。

- 外部場所または誘惑の少ない場所で、まず**最初の3問だけ**一人で実施。
- 終わったらすぐ確認する。
- 成功したら次回5問 → 1枚へ伸ばす。

**C/Dの概念を学んでいる最中に、同時に完全独力化を求めない。**

### K. 1日の現実的な学習量
- 英語+数学で実質約1時間かかるため、遅れを取り返す目的で1日に複数DAYを重ねると持続しにくい。
- 原則は各科目1日1DAY。遅れは問題量・重複反復の圧縮と、後続DAYへの再利用で回収する。

### L. 自力着手は固定特性ではなく改善する
- 共同での成功、紙面構造の固定、例から始める流れを数日積み重ねた後、自分でプリントへ取り組める場面が出てきた。
- 現時点では安定した習慣と断定しないが、`一人ではできない` を固定条件にせず、起動条件が学習されて改善する可能性を前提にする。
- 自走が出ている間は管理を増やしすぎず、同じプリント構造・1日量を維持して成功回数を積む。

## 7. 報酬・本人の関心の使い方

- 開始前に「この1枚が終わったら次は本人が関心のある行動」と、終了点を短く明示する。
- `全部完璧にできたら` ではなく、**決めた1枚/区間を完了したら**に結びつける。
- 報酬は理解の代替ではなく、着手・再開の摩擦を下げるために使う。

## 8. 親が残す記録

各セッションで必要なのは次だけ。

- 対応INDEX
- 理解状態 A/B/C/D
- ヒント有無
- 例・途中式があれば戻れたか
- 実行環境: マンツー / body-double / 独力、場所
- 離脱した場合: **何問目ではなく、どの認知負荷・環境で離脱したか**

「何分集中できたか」単体より、**何なら起動し、何で止まるか**を蓄積する。
