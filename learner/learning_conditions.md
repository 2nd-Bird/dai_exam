# 長男 — 学習が起動する条件 / 起動しない条件

updated: 2026-08-24

この文書は診断名から一般化するためではなく、実際の学習場面の観察から、教材設計と伴走方法を更新するための運用メモ。

## 1. 現時点の中心課題

**理解力不足より、課題着手・動機の起動が最大のボトルネック。**

簡単すぎる問題でも「分かるからできる」とはならない。  
一人でプリントに向かう条件では、丸をつけるだけ・1語入れるだけでも着手しないことがある。

逆に、興味・状況・対話が立ち上がると、同じ文法を意味に合わせて口頭で使える。

したがって教材の目標は、
`説明をもっと簡単にする` だけではなく、
**「意味のある状況 → とっさに言う → 最小限だけ書く」までを課題の中に埋め込むこと。**

## 2. うまくできる流れ

### A. 状況が先にある
- 人物、目的、危機、違和感、笑いなどがある。
- 「正体不明のプレイヤーがいる。誰だこいつ？」のように、発話する理由が明確。
- 文法問題ではなく、まず「この状況で何と言う？」になる。

### B. 本人が状況の中に入る
- 本人自身、ゲームのキャラクター、海外プレイヤーなどを登場させる。
- 正解を当てるより、役になって言う方が起動しやすい。

### C. 父とのライブなやりとり
- 父が横にいるだけでなく、反応を見て状況を動かすと強く起動する。
- ただし毎回ゼロから即興するのはコストが高い。
- プリント側に状況を用意し、父は「点火・演出の増幅」に寄せる。

### D. 構造をモジュールとして説明する
理解は速く、単なる丸暗記より構造の組み替えが効く。

例:
`you do`
→ 疑問のスイッチ `do`
→ `do you do?`
→ 「何を？」の `what`
→ `do you do what?`
→ whatを前へ
→ `What do you do?`

「なぜそうなるか」を短い変形として見せると入りやすい。

### E. 音・リズム・気分を使う
- 聴覚からの取り込みが強い。
- 抑揚、リズム、キャラクターの気分を乗せた発話を聞かせ、同じ感じで言わせると反復が成立する。
- 書字反復ではなく、口頭の3〜5連発で自動化回数を稼げる。

### F. 実際に英語が役立つ文脈
- ゲームの音声チャットで英語話者のやりとりに混ざることがある。
- 英語は完全な学校課題ではなく、実際の通信手段として薄く意味を持っている。
- 教材はこの実体験へ接続する。

### G. 数学は「途中を外に出す」と安定する
- 負の乗法を頭の中だけで処理すると誤答が出るが、`(-2)×(-2)=2×(-1)×2×(-1)=4×1=4` のように分解を書くと正答できる。
- 累乗も指数を見て一度、同じ数の積へ展開すると戻れる。
- 現段階では途中式は冗長な手続きではなく、**思考を保持する外部メモリ**として機能する。
- 安定してから省略する。最初から暗算化を目標にしない。

## 3. できない / 起動しにくい流れ

### A. プリントを置いて一人でやらせる
- 理解済み・極端に簡単でも着手しない。
- 「できる問題なら一人で進む」は現状成立しない。

### B. 場所を変えれば自動的に学習モードになる、という前提
- 「図書館でやる」と決め、図書館が休みだと、児童館など代替場所へ自動的には切り替わらない。
- 場所そのものより「その場で何を始めるか」の起動が必要。
- 今後は `図書館が休み→児童館でAだけ` のような代替ルールを事前に明示する。

### C. 未実施を積み残しとして見せる
- 「昨日の裏をまだやっていない」「Bが残っている」は、枯渇しやすい意欲をさらに減らす。
- 未実施技能は後続DAYの新しい状況へ埋め込み、古い紙を負債化しない。

### D. 書くことを理解確認の唯一の手段にする
- 口頭なら意味に応じて正しく使える場面でも、筆記開始が強い障壁になる。
- 1周目は口頭利用を正式に評価し、書字は本番答案へ接続する少数問題に限定する。

### E. 夕食後・眠気が強い時間
- 共同なら進めても、利用可能時間が短くなる。
- 高優先内容をAに置き、Bは未実施でも致命傷にならない設計にする。

### F. C段階の概念と完全独力を同時に要求する
- まだ概念が不安定な内容を、暗算・一人・自宅の条件で同時に処理させると、数学理解と実行機能のどちらで止まったか分からなくなる。
- 「一人でできない = 分かっていない」とは判定しない。

## 4. 問題プリントの設計原則

1. **状況を先に印刷する。**
2. `まず口で言う → 1語穴埋め → 必要な箇所だけ全文` の順。
3. 1つの状況で1つの文法判断に絞る。
4. Aに最重要内容を置く。Bは余力枠。
5. 前日の未実施ページをそのまま再提出しない。
6. 前に扱った文法は、新しい状況の材料として自然に再登場させる。
7. 各DAYに「声だけ3連発」など口頭反復を入れ、少ない演習量を補う。
8. 説明は短くするが、本人が構造へ食いついたらモジュール型の説明を許容する。
9. 父との脱線は一律に排除しない。**学習を起動するための脱線**は必要コストとして扱う。
10. ただし脱線後は、同じ構文を口頭で数回使って学習量へ変換する。
11. 数学で符号・累乗・計算順序が不安定な間は、**途中1行を書くこと自体を正解手順に含める。**
12. 遅れを取り返すときは範囲を削らず、問題数・重複反復を減らす。1枚に新規事項を詰め込まない。

## 5. 当面の評価軸

各技能を以下に分けて見る。

- `理解`: 文の仕組みを説明・選択できる
- `状況利用`: 場面に応じて口頭で使える
- `即時想起`: ヒントなしで短時間に出る
- `答案化`: 手書きで必要な形を再現できる
- `自力着手`: 一人で課題を開始できる

現状、`理解 / 状況利用` は高くなりやすい一方、
`即時想起 / 答案化 / 自力着手` が別ボトルネックになっている。

これらを1つの「できる / できない」に潰さない。

数学についても同様に、`概念理解 / 手順再現 / 暗算化 / 自力着手` を分ける。  
たとえば負の乗法は、現状 `概念理解=C、途中式ありの手順再現=B〜A、自力着手は別評価` のように記録する。

## 6. 独力化の標準フロー

独力化は一気に要求せず、次の順で移す。

### Phase A — 共同で獲得
対象: 新規内容、C/D。

1. 場所と開始時刻を先に固定する。
2. 最初の1〜2問を父と開始する。
3. 例・図・途中式を使って少数問だけ処理する。
4. **1枚を終了単位**にする。
5. 父は「どこで止まったか」を記録する。

### Phase B — body-double
対象: B、手順を見れば戻れる内容。

- 同じ机/部屋にいるが、最初は口を出さない。
- 止まったときだけ例を指す、またはヒントを1文。
- 3問程度連続で滑らかなら、その区間を独力候補にする。

### Phase C — 短い独力
対象: Aまたは安定したB。

- 外部場所または誘惑の少ない場所で、まず**最初の3問だけ**一人で実施。
- 終わったらすぐ確認する。
- 成功したら次回5問 → 1枚へ伸ばす。

**C/Dの概念を学んでいる最中に、同時に完全独力化を求めない。**

## 7. 報酬・本人の関心の使い方

- 開始前に「この1枚が終わったら次は本人が関心のある行動」と、終了点を短く明示する。
- `全部完璧にできたら` ではなく、**決めた1枚/区間を完了したら**に結びつける。
- 報酬は理解の代替ではなく、着手・再開の摩擦を下げるために使う。

## 8. 親が残す記録

各セッションで必要なのは次だけ。

- 対応INDEX
- 理解状態 A/B/C/D
- ヒント有無
- 例・途中式があれば戻れたか
- 実行環境: マンツー / body-double / 独力、場所
- 離脱した場合: **何問目ではなく、どの認知負荷・環境で離脱したか**

「何分集中できたか」単体より、**何なら起動し、何で止まるか**を蓄積する。
